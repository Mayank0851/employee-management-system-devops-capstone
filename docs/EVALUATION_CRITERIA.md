# Evaluation Criteria

## Repository Quality

- The repository should be organized and easy to navigate.
- The project should reflect a professional handover from development to operations.
- Unnecessary generated files and temporary artifacts should be removed.

## Configuration Management

- Environment variables should be used for configurable settings where appropriate.
- The repository should include a clear environment example file.
- Configuration should be documented and easy for the next engineer to extend.

## Container and Automation Readiness

- Docker assets should be structured, readable, and suitable for future student completion.
- Compose and workflow files should include clear placeholder sections for implementation.
- The repository should clearly preserve the expectation that students still need to complete Docker Compose, GitHub Actions, Amazon RDS, ECS, ECR, CloudWatch, S3, and CI/CD work.
- The repository should demonstrate DevOps best practices without overstepping into solution implementation.

## Documentation and Handover Value

- Project requirements should be clearly defined.
- Submission expectations should be explicit.
- Evaluation criteria should align with the responsibilities of a DevOps handover team.
